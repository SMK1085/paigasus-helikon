### Issues

**Important — `README.md`, route table row 4, description column**

&gt; `README.md` line 94 (diff): `| GET | /agents/{name}/runs/{id}/events | Replay or stream events for a run (HTTP or WebSocket upgrade) |`

The "HTTP or" part is wrong. `src/handlers/events.rs` (line 50) requires `ws: WebSocketUpgrade` as an extractor; there is no HTTP fallback. A plain `curl http://…/events` call will receive a 400/upgrade-required error from axum, not a streamed JSON response. The description should say "WebSocket only" or "subscribe to run events via WebSocket".

**Minor — README inline usage example vs. `curl_server.rs` bind address**

`README.md` line 79 (diff) shows `.serve("0.0.0.0:8080")`, while `examples/curl_server.rs` (line 218) uses `"127.0.0.1:8080"` and its `//!` curl snippets reference `localhost:8080`. Both addresses work for the curl examples (localhost resolves to either), but the two "canonical" code samples show different addresses. Aligning them (either direction) would reduce reader confusion.

  ### QUESTIONS
  
  - On re-check, a guard `Ask` or a policy `AskUser` that did not fire at defer time (because the configuration changed) counts as answered. Is that intended, or must a new ask point deny?
  - ADR (g) says "any Deny wins" and also "do not fire PreToolUse again". So a `PreToolUse` deny that would apply at resume time is never evaluated. Is that intended?
  - Can a run resume when its context has the flag off?
  - Is a direct `agent.run` call with the flag on supported? It can emit `RunDeferred`, but nothing can resume it without a runner.
  - When the flag is off, must a policy `Defer` fall back to the handler (as for `AskUser`) instead of becoming `Deny`?
  - Which copy does the host show the approver: `RunDeferred.calls` or the stored `ToolDeferred`? The fix for the call-id BLOCKER depends on one source of truth.
  
  ## What's good
  
  - The flag is off by default, and every path where it is off maps `Defer` to `Deny`. `AgentAsTool` (`/Users/smaschek/dev/paigasus/paigasus-helikon/.claude/worktrees/sma-803-deferred-tool-calls/crates/paigasus-helikon-core/src/agent_as_tool.rs:124`), MCP, evals, the CLI and the Temporal worker all build their contexts with `RunContext::new` or `ephemeral`. So in all of these the flag is off by construction, and the four copy sites are handled correctly.
  - All-or-nothing resolution, results before new input, and a synthetic result on cancel form one clear invariant. Because the results come first, an append that stops partway still leaves a valid log.
  - The compatibility work is careful:
    - A new terminal event instead of a field on `RunCompleted`.
    - `TransitionInput::ToolResults` stays unchanged for Temporal.
    - Explicit `kind()` and `project()` arms.
    - The `CompactingSession` guard.
    - The rollback note in the changelog.

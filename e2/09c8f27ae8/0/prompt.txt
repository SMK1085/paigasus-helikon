## 1. How Entire attribution actually works (verified from the installed CLI, not guessed)

The link is an **`Entire-Checkpoint: &lt;checkpoint-id&gt;` trailer in the real commit's message**. Everything else is payload storage. Proof — `entire checkpoint explain` states the mechanism in its own failure text:

```
$ entire checkpoint explain 66bdd8f
✗ No associated Entire checkpoint
  commit   66bdd8f
  reason   no Entire-Checkpoint trailer
  hint     the commit exists but was not created during an Entire session
```

The full machinery, all confirmed in this repo:

| Piece | Where | Verified |
|---|---|---|
| Trailer injection | `.git/hooks/prepare-commit-msg` → `entire hooks git prepare-commit-msg` | hook file read |
| Condense after commit | `.git/hooks/post-commit` ("condense session data if commit has Entire-Checkpoint trailer") | hook file read |
| Re-link after amend/rebase | `.git/hooks/post-rewrite` | hook file read |
| Push checkpoint data | `.git/hooks/pre-push` (chains to `pre-push.pre-entire` = cargo-husky's) | hook file read |
| Checkpoint payload storage | commits on `refs/heads/entire/checkpoints/v1`, mirrored to `origin` (both at `92a8c9d`, in sync) | `for-each-ref` |
| In-flight session | ephemeral "shadow branch" `entire/&lt;HEAD-short-sha&gt;-e3b0c4` | `refs/heads/entire/66bdd8f-e3b0c4` |
| Per-worktree session state | `.git/entire-sessions/&lt;uuid&gt;.json` | dir listed |
| Enablement flag | `.entire/settings.json` → `{"enabled": true, "telemetry": true}` | file read |

Checkpoint commits themselves carry `Entire-Session:`, `Entire-Strategy: manual-commit`, `Entire-Agent: Claude Code`, `Ephemeral-branch:` trailers — but those live on the checkpoints branch, **not** on your real commits. **Git notes are not used at all** (confirmed).

Config is fine and is *not* a cause: `entire status` → `● Enabled · manual-commit · branch main`, `entire agent list` → `✓ claude-code`, `entire auth status` → logged in as `@SMK1085`, repo auto-detected as `gh/SMK1085/paigasus-helikon`, `.claude/settings.json` has all six Entire hooks wired.

## 3. Root causes, ranked

### RC1 — GitHub's squash setting discards the trailer on **every** merge (100% loss, unconditional)

```json
{"allow_merge_commit": false, "allow_rebase_merge": false, "allow_squash_merge": true,
 "squash_merge_commit_title": "PR_TITLE", "squash_merge_commit_message": "BLANK"}
```

`squash_merge_commit_message: "BLANK"` means every merge to `main` produces a commit with an **empty body**. Squash is the *only* permitted merge method, so no commit trailer can ever reach `main` — by configuration, not by accident.

The proof pair is airtight: `28762f1d` (body = long description + `Co-Authored-By` + `Entire-Checkpoint: 11b8d44be2ce`) merged as `2d90ccf`, whose entire body is:

```
Co-authored-by: Claude Opus 5 (1M context) &lt;noreply@anthropic.com&gt;
```

GitHub special-cases `Co-authored-by:` and re-appends it under BLANK; it drops everything else. `ad59f4b`'s body is completely empty. `66bdd8f` is a single-parent squash of 34 commits.

**This alone guarantees zero attribution on `main` even if every other layer worked perfectly.**

### RC2 — Entire is completely inert inside git worktrees (loses the work at the source)

`.entire/` and `.claude/` are **untracked**, so `git worktree add` — which only materializes tracked files — creates a checkout where Entire does not exist. Verified directly:

```
$ cd /private/tmp/.../scratchpad/main-ab &amp;&amp; entire status
○ not set up (run `entire enable` to get started)
$ ls .entire .claude
No such file or directory   (both)
```

Consequence for the SMA-343 work, traced end to end:

- Session `a284e209-3551-4620-8e8e-99d2f825aff0`, prompt `/feature-factory:feature-pipeline SMA-343`, started Jul 18 12:21 **in the main checkout** — Entire captured the launch prompt: `.entire/metadata/a284e209-.../prompt.txt` (41 bytes).
- At 12:49 the pipeline moved into `.claude/worktrees/sma-343-runtime-actix`. Same session id, new cwd. Claude Code reloads project settings from cwd; there is no `.claude/settings.json` there, so the Entire hooks stopped firing, and no `.entire/settings.json` means the git hooks that *do* fire (hooks are shared via `$GIT_COMMON_DIR`) see a disabled repo.
- Result: `.entire/metadata/a284e209-.../` contains **only `prompt.txt`, no `full.jsonl`** — the one session directory out of five that is missing a transcript. Zero checkpoints, zero trailers on 34 commits.
- The transcript is **not lost** — Claude Code kept it: `/Users/smaschek/.claude/projects/-Users-smaschek-dev-paigasus-paigasus-helikon--claude-worktrees-sma-343-runtime-actix/a284e209-3551-4620-8e8e-99d2f825aff0.jsonl` (3.6 MB).

Note `.git/info/exclude` line 12 already carries `**/.claude/worktrees/`, so the worktree dir itself is hidden — consistent with this being an established workflow, which makes RC2 systemic, not a one-off.

### RC3 — Main-checkout orchestrator sessions produce nothing to link (minor but compounding)

`.entire/logs/entire.log` shows, on essentially every turn of sessions `627e2e93`, `7c1f131e`, `c79dca16`:

```

"msg":"no file changes detected, skipping task checkpoint"
```

This is *correct* Entire behaviour — the orchestrator session delegates all edits to worktrees and subagents, so the main checkout genuinely has no diff. But it means even the tracked sessions generate no checkpoint. The log also shows the shadow branch chasing HEAD as merges land: `moved shadow branch (HEAD changed during session) from entire/1bc55cb-e3b0c4 to entire/66bdd8f-e3b0c4`, and `entire status` currently warns `! attribution base diverged after history movement`.

### RC4 — `.entire/` untracked is the mechanical enabler of RC2 (and a `git add -A` hazard)

Not itself a cause of lost attribution (checkpoint payloads ride the `entire/checkpoints/v1` branch, which *is* pushed to origin), but it is exactly why worktrees don't inherit Entire, and it shows as `?? .entire/` in `git status` alongside the known `.env` hazard.

**Ruled out:** git hooks are present and correct; Entire is enabled and authenticated; the checkpoints branch is pushed and in sync with origin; there is no missing project id or auth flag; git notes are not part of the design.

### Step 1 — Make the trailer survive the squash **[MUTATES GitHub repo settings]**

```bash
gh api -X PATCH repos/SMK1085/paigasus-helikon -f squash_merge_commit_message=COMMIT_MESSAGES
```

Leave `squash_merge_commit_title=PR_TITLE` alone — `pr-title.yml` and CLAUDE.md's "PR title becomes the squashed commit" rule are unaffected; only the body changes.

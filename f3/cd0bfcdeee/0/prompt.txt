**Important**

The actual surface is `POST /agents/{name}/runs` (with `?stream=sse` / `?mode=async` query params, not separate paths), WebSocket `/agents/{name}/runs/{id}/events`, and traits `ContextProvider` / `AuthLayer`. Because this is the stub-ascend flow (the PR bumps its own version and publishes on merge with no separate release-plz PR), this hand-written entry is the **permanent** 0.1.0 crates.io changelog and GitHub release body — it ships materially wrong. Trivial to fix; worth doing before merge.

**Minor**
2. **SSE/WS start-error path emits no synthetic error frame** (`handlers/runs.rs` `sse_response` / `handlers/events.rs`). On an outer `Err(RunError)` the writer sets `start_error` and `mark_terminal()` with no event appended, so streaming subscribers get a clean empty close — but spec §6 says "streams emit a final synthetic error frame, then close." One-shot correctly returns 500; only the streaming transports diverge, and only in the rare start-error case (never reachable with the default in-memory provider). No hang/leak. Defer, but note it.
3. **OpenAPI doc stub mislabels the WS endpoint** (`handlers/openapi.rs` `_events_doc`): it describes `/agents/{name}/runs/{id}/events` as "Server-Sent Events stream of AgentEvents", status 200 — it is a WebSocket endpoint. This inaccuracy is served to API consumers in `/openapi.json`.
4. **OpenAPI version wording drift**: README/crate docs say "OpenAPI 3.1"; `docs/book/src/concepts/axum-server.md` says "OpenAPI 3.0" (twice). utoipa 5.x emits 3.1, so the book is the wrong one.
5. **No CI gate compiles `runtime-axum` with `--no-default-features`.** Gating is correct by inspection, but spec §9's "default-features=false compiles" claim is unverified by any standing gate (only `--all-features` runs in CI). Consider a follow-up build-matrix entry.

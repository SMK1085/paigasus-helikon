#### Important (Should Fix)

1. **The security-boundary docs promise a worker-side posture knob that does not exist.** `crates/paigasus-helikon-runtime-temporal/src/lib.rs` ("Worker-Side Posture and Security Boundary"): *"The worker fabricates its own `RunContext&lt;Ctx&gt;` from its configured context factory, **plus optional permission and redaction settings configured on the worker itself**"* — and the spec (§5.8: "plus an optional worker-side permission/redaction configuration") and CHANGELOG ("making its permission/redaction settings authoritative") repeat it. As-built, `TemporalAgentWorkerBuilder` has **no** permission or redaction configuration whatsoever; every activity builds `RunContext::ephemeral(ctx).with_cancel(...)` (activities.rs `TypedRuntime::run_context`), i.e. fixed defaults: `PermissionMode::Default` + no policy → **allow**, built-in destructive guards on (Ask→Deny, no handler), `redact_output = true` with env-sourced secrets only, no way to add deny rules, `extra_secrets`, or a policy. The defaults fail safe, so this isn't Critical — but (a) docs.rs 0.1.0 will document a security-relevant setting a user cannot find, and (b) this is an unflagged deviation from the approved spec (the plan promised the option; the implementation dropped it silently). **Fix before PR:** either add the builder knob, or (cheaper, defensible for v0) reword lib.rs + CHANGELOG + spec §5.8's "as-built" posture to: *fixed v0 defaults — redaction on, destructive guards on, no custom rules; worker-side posture configuration is future work alongside the serializable-Ctx seed.* The same nuance applies client-side: a `RunContext` handed to `TemporalRunner` with deny rules/`DontAsk`/policy is silently ignored for tool execution — the "caller's permissions do not propagate" doc covers this, but a sentence naming those exact fields would prevent the worst misreading.

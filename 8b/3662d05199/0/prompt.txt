#### Important (Should Fix)
- **SSE mode never drives the runner stream to terminal (or cancels) on early client disconnect — unlike `runtime-axum`, and in violation of a documented cross-crate contract.** `run_sse` (`invoke.rs:292-313`) wires the raw `runner.run_streamed(...).events` stream directly as the axum SSE response body via `.map()`, with no decoupling layer. `TokioRunner::run_streamed`'s `finalize(&amp;session, &amp;recorder)` call only fires *inside* the stream generator once a terminal event is reached while being polled (`crates/paigasus-helikon-runtime-tokio/src/lib.rs:221-232`); if the HTTP connection drops before that point, axum stops polling the body, the generator is dropped mid-flight, and `finalize` never runs — silently losing that turn's session persistence. `Runner::run_streamed`'s own doc is explicit about this risk (`crates/paigasus-helikon-core/src/runner.rs:95-98`: "a consumer that drops the stream early may skip the finalize step"). `runtime-axum` solves exactly this by spawning a detached writer task (`spawn_writer`, `runs.rs:266-313`) that drains the runner stream into an `EventLog` independent of the response's lifetime, plus an owned `DropGuard` over the cancel token (`SseState.disconnect`, `runs.rs:330-358`) so a disconnect cancels the run and still lets the writer observe a real terminal event. AgentCore's handler additionally never retains a clone of its `cancel` token (`invoke.rs:241`, `cancel` is moved straight into `ctx.build`), so it also fails to honor `ContextProvider::build`'s documented parameter contract: *"cancel — cancellation token tied to the lifetime of this run; **the server cancels it when the client disconnects**"* (`crates/paigasus-helikon-runtime-axum/src/context.rs:83-84`). Net effect: an AgentCore SSE client that disconnects mid-run (network blip, timeout, gateway restart) silently breaks the "same id ⇒ same session" continuity contract for that turn, with no test coverage or documentation of the trade-off. This was a named review risk and reproduces on inspection, not speculation.
  - Fix options: mirror `runtime-axum`'s writer-task + `DropGuard` pattern (heavier, but full parity), or at minimum retain a `DropGuard` on `cancel` and document/accept the finalize-on-disconnect gap explicitly in `invoke.rs`'s module docs if the single-shot AgentCore model is judged to make it acceptable.

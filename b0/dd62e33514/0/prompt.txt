  ## What's good
  - **The cycle and the release model are correct, and the repo has used them before.**
    - (1) Core integration tests and the testkit link the same core rlib. The core lib unit-test build gets the testkit as an unused extern, which is harmless. Core has no features, so `--all-features` cannot make a second core build. `tokio` and `tokio-test` use the same pattern.
    - (2) Cargo removes path-only dev-dependencies from the published manifest. `deny.toml:108-111` (`allow-wildcard-paths = true`) already allows them. `scripts/check-release-gaps.sh:190` skips packages with `publish = []`.
    - (3) The full pattern already went through release-plz from SMA-330 to SMA-805 (`docs/superpowers/specs/2026-06-28-sma-330-production-session-backends-design.md:64,167`). Cite this precedent in "Known limit", because it is stronger than the core↔macros case.
  - **The code confirms that behaviour stays the same.** The two `assert_tool_calls_paired` bodies are byte-identical today, and so are the two `with_late_transfer_results` bodies. Both `MockModel`s return `"no more scripted responses"` (core `tests/common/mod.rs:49`, runtime-tokio `tests/common/mod.rs:54`) and ignore `cancel`.

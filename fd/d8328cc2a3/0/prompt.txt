  - **§4 rationale is false: a closed `tool_use` block can be a truncated call** - §4 says "a closed `tool_use` block is a complete call". As I understand the Anthropic stream shape, it also sends `content_block_stop` for a block that `max_tokens` cuts, before `message_delta`. I found no capture of this in the repo, so confirm it. The block-stop emit then gives a named call with `args_delta: ""`. Core turns that into `{}` (`crates/paigasus-helikon-core/src/model.rs:645-649`). So the result is a `{}` call under `Finish(Length)`, which is the result that §4 forbids for the net. | Why it matters: the limit on the net has no consistent basis, and a later reader will trust a wrong statement. The code risk is mostly not new. The captures always send a first empty delta (`crates/paigasus-helikon-providers-anthropic/tests/fixtures/parallel_tool_use.txt:31-33`), so the real wire already gives this `{}` call under `Length` today. | Suggested fix: Rewrite §4 to say that the block-stop emit copies what the empty-delta wire already does, under every stop reason. Add a unit test that pins block stop + `max_tokens`. File a Linear issue for "a `ToolCall` with a `Length` finish still runs" (core / agent loop).
  
  - **The anthropic emit drops the start event's `input`** - `ContentBlockHead::ToolUse` already parses `input` (`crates/paigasus-helikon-providers-anthropic/src/sse.rs:72-74`, marked `#[allow(dead_code)]`), and `consume` drops it (`src/stream.rs:124`, `{ id, name, .. }`). §6.1 always sends `args_delta: ""`. No stream today has the no-delta shape. Its most likely source is a proxy or an Anthropic-compatible server that puts the whole input in `content_block_start` (the non-streaming shape) and sends no delta. | Why it matters: for that shape, the change turns today's dropped call into a call that runs with `{}` in place of the real arguments. Today the failure is visible (`Finish(ToolCalls)` with no call). After the change it is a silent wrong tool call. The chance is low, and the fix is small. | Suggested fix: Keep `input` in `BlockState::ToolUse`. At the block-stop emit and in the net, send `serde_json::to_string(&input)` when `input` is a non-empty object. Otherwise send `""`. Add one unit test. Bedrock is not affected: its `ToolUseBlockStart` has only `tool_use_id` and `name` (aws-sdk-bedrockruntime 1.157.0, `src/types/_tool_use_block_start.rs:8-10`).

Add `terminal_emitted: bool` and set it when `finish_events` returns a non-empty `Vec`. In the `ContentBlockStop` arm, return early when it is set.

## Verdict: NEEDS REWORK

The §3 implementation is sound — I verified `take_while` compiles, satisfies `Send + 'static`, and the pull-then-check subtlety genuinely is unobservable here. But §4 is the entire deliverable of AC #2, and it does not hold up: §2 claims test coverage that neither proposed test provides, and §4.2's `RetryingModel` pinning is a near-duplicate of an existing test paired with a mutation check that doesn't exercise the property it claims to pin. ### QUESTIONS

- The spec dismisses registering `MockModel` as a conformance *subject*, and I agree with the reasoning (`Ok(None) =&gt; break` with `fired == false` at `provider-stream-conformance/src/lib.rs:461` yields `Violation::InsufficientEvidence` at lib.rs:404). But `check::classify(&amp;events, scenario, cancelled)` is a pure function over `&amp;[Result&lt;ModelEvent, ModelError&gt;]` with no HTTP dependency. Was reusing `classify` directly on the drained events considered — so `MockModel` is held to the same canonical rule set as the providers rather than to hand-rolled asserts? If the blocker is that `tests/provider-stream-conformance` is a separate non-published crate that `evals` cannot dev-depend on without a new path dep, say so; that is a legitimate answer and worth one sentence.
- Do you intend the new doc sentence to promise that the stream *wakes* on cancellation, or only that it *observes* on the next poll? With `is_cancelled()` a consumer who stops polling never sees the end. Note `crates/paigasus-helikon-core/src/agent.rs:946` drains the model stream with a bare `while let Some(evt) = model_stream.next().await` and no cancellation race — it relies entirely on the model stream self-terminating. That is fine for a synchronous mock, but the wording should not imply more than `is_cancelled()` delivers.
- §2 says a pre-cancelled `invoke` pops its script and returns empty. Should the empty-stream case emit a `tracing::debug!`? A silently-consumed script with zero events is exactly the shape that will confuse someone debugging an eval run that reports "no more scripted responses" one call earlier than expected.

## What's good

- **The core design decision is right and well-argued.** Choosing a synchronous `is_cancelled()` observation over `select!` on `cancelled()` is correct for a stream that never parks, and the "one script consumed per `invoke` stays unconditionally true" argument for popping on a pre-cancelled invoke is the better of the two options — the alternative really is two rules where one will do.
- **The `take_while` pull-then-drop analysis is correct**, and I could not find an observable consequence for `MockModel` — the stream owns the `Vec&lt;ModelEvent&gt;` exclusively and dropping an unconsumed item has no side effect. Worth keeping the sentence; it pre-empts an obvious review objection.
- **The non-goal on the conformance suite is genuinely reasoned, not hand-waved** — it correctly identifies that the harness's gate/quiescence mechanism (`provider-stream-conformance/src/lib.rs:457-477`) cannot apply to a synchronous in-memory stream, and that the missing-evidence floor would reject it. That is the right call for the right reason.
- **The determinism claim for `cancel_after_content_ends_stream_without_finish` checks out exactly as stated** — `retry.rs:223-227` is `biased` with `cancelled()` first, so a ready token beats a ready item with no race. That test is the one genuinely valuable addition in §4.2; keep it.</result>

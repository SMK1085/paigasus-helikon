### Issues

**Minor — `dto.rs:140`: `output = Some("")` for a text-free `AssistantMessage`**

When the last `MessageOutput` carries an `AssistantMessage` whose `content` contains only non-text parts (`Image`, `Audio`, `ToolUse`, etc.), the `text` accumulator stays empty and `output` is set to `Some("")`. The field-level doc at `dto.rs:98-99` says "`None` if the run produced no assistant output." An assistant message with no text is indistinguishable from "no assistant output" from the caller's perspective, so `Some("")` contradicts the stated contract. The fix is to only set `output = Some(text)` when `!text.is_empty()`, and otherwise leave `output` as it was (preserving whichever prior message had text, or staying `None`):

```rust
if !text.is_empty() {
    output = Some(text);
}
```

**Minor — `dto.rs:219-248`: test does not verify "last wins" semantics**

`response_from_events_extracts_output_and_usage` uses a single `MessageOutput` before the terminal event. The implementation is correct (assigns, not appends), but the test does not demonstrate the distinguishing behavior: two `MessageOutput` events where only the second's text should appear in `output`. A second test (or an additional assertion) with `["first", "second"]` and `assert_eq!(r.output.as_deref(), Some("second"))` would give confidence.

**Minor — `dto.rs:219-248`: `AgentEvent::RunFailed` path is untested**

No test exercises the `RunFailed { error }` branch of `from_events`. The `status = Failed` / `error = Some(e)` path through `dto.rs:146-149` is correct by inspection, but a three-line test would close the gap.

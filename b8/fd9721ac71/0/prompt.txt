**Runtime injection is genuine.** `openapi_json` (openapi.rs:106-110) calls `state.agents.values().map(|a| format!("- `{}`: {}", a.name(), a.description()))` at request time. ### Issues

#### Minor

**`tests/openapi.rs:38-42` — path/schema assertion uses `||` instead of `&amp;&amp;`**

```rust
let has_runs_path = body_str.contains("/agents/{name}/runs");
let has_agent_info_schema = body_str.contains("AgentInfo");
assert!(
    has_runs_path || has_agent_info_schema,  // &lt;-- OR
    …
);
```

The brief says the test must assert the spec contains "the `/agents/{name}/runs` path" (a positive requirement). With OR, a spec containing only the `AgentInfo` schema but no paths would pass the assertion. In practice the spec contains both, so the test passes correctly — but the OR makes the test weaker than intended and will not catch a future regression where path stubs are removed while schemas remain. Should be `&amp;&amp;`.

**`openapi.rs:78-88` — 200 sync-run response has no body schema**

`_create_run_doc`'s 200 response entry (openapi.rs:78) has only `description = "Completed synchronous run"` — no `body`. This satisfies the constraint ("RunResponse must not be a ToSchema") but leaves API clients without any schema for the most common response body. A comment-only note like `// 200 body intentionally untyped — RunResponse is not a ToSchema` would clarify the deliberate omission.

Neither issue is a correctness bug or a failing constraint.

## Verdict: NEEDS REWORK

The site inventory (§3) is accurate — I independently re-counted all 97 sites and every file:line in §3.1–§3.6 checks out — and the D5/§4.1 reasoning about the existing scanner is well-grounded. But three things must be fixed before code is written: §4.4 specifies an assertion the §4.1 API cannot produce; §6's stated release outcome is materially wrong (this is a caret-incompatible `0.5.18 → 0.6.0` on `core`, cascading a re-pin to ~19 crates, not "six minor bumps plus the facade"); and §7.4's "unaffected" claim is falsified by the vendored `tracing-opentelemetry` source. ## Findings

### BLOCKER

- **§6's expected release outcome is wrong, and the real cost is unpriced** — `paigasus-helikon-core` is at `0.5.18` (`Cargo.toml:151`). A breaking marker on a 0.x crate yields `0.6.0`, which is **caret-incompatible** with the `version = "0.5.18"` requirement that all 19 dependents carry via `[workspace.dependencies]`. Same for the runtimes: `runtime-tokio 0.1.21 → 0.2.0`, `runtime-axum 0.2.3 → 0.3.0`, `runtime-actix 0.2.3 → 0.3.0`, `runtime-temporal 0.4.3 → 0.5.0`, `runtime-agentcore 0.2.6 → 0.3.0`. §6 says "with `paigasus-helikon` cascading" — in fact `-mcp`, `-tools`, `-evals`, `-sessions-sqlite/-postgres/-redis`, `-cli`, and all five providers each need a manifest re-pin and a bump too. | Why it matters: the author will check the release PR against a wrong expectation and may read a correct 20-crate release PR as a runaway; and a purely observational change becomes a semver-incompatible release of the entire SDK, which is a decision that deserves to be recorded, not discovered. It also weakens D4's rejected alternative — an ordinary `feat(core):` *does* appear in the CHANGELOG's Features section, so "an operator who reads CHANGELOGs and not the book gets no warning at all" is false; what `!` buys is the version signal, at the price of a workspace-wide incompatible release. | Suggested fix: state the concrete expected version for each of the six crates and the full list of cascaded dependents in §6; add one paragraph to D4 pricing the caret-incompatibility and explicitly accepting it.

- **§4.4's third assertion cannot be implemented with the §4.1 API** — "the number of `target:` arguments the walker sees must equal the number of string literals `scan_target_literals` returns". `scan_untargeted` returns only untargeted sites; `scan_target_literals` returns only literal targets. Neither yields the count of `target:` arguments seen. | Why it matters: this is the *only* mechanism stopping a computed target (`target: SOME_CONST`) from silently routing events out of the namespace — §4.1 calls that out as the reason the assertion exists — and as specified it is unbuildable, so it will be quietly dropped or reinvented differently by whoever implements it. | Suggested fix: change the signature to `pub fn scan_targets_of_invocations(src: &amp;str) -&gt; Result&lt;Vec&lt;(usize, Option&lt;String&gt;)&gt;, MismatchedDelimiter&gt;` (`None` = non-literal target) and drop `scan_target_literals`; or add a third function returning the invocation/targeted counts. Pin the choice in the spec.

- **The `crates/*/src` walk contains 77 non-tracing `target:` tokens across 29 files, three of them followed by a string literal — the spec says this "costs nothing"** — §4.2 claims `#[cfg(test)]` modules inside `src/` cost nothing "because none contains a `tracing` macro today". Non-literal `target:` fields also exist in `core/src/agent.rs`, `core/src/handoff.rs`, `core/src/loop_state.rs`, `core/src/permission.rs`, `core/src/swarm.rs`, `tools/src/web/fetch.rs`, `tools/src/net/proxy.rs`, `runtime-temporal/src/error.rs`. Several of these sit in the same files as real tracing sites, so the mistake is easy to make. | Suggested fix: name `command_match.rs:436` in §4.5 as a **required** regression fixture ("a `target:` struct-field initializer with an adjacent string literal must be invisible to both new scanners"), and add a step to correct the stale doc comment at `tests/workspace-lints/src/lib.rs:190-192`.

### MAJOR

- **§7.4's `tracing-opentelemetry` claim is falsified by the source it cites** — `with_target` defaults to **`true`** (`tracing-opentelemetry-0.33.0/src/layer.rs:667`; the doc at `:880` says "By default, the target attribute is enabled"), and `layer.rs:1185` pushes `KeyValue::new("target", attrs.metadata().target())` onto every exported span, with the same for events at `:1370-1376`. So every span already exported to Langfuse/Jaeger/Honeycomb carries `target = "paigasus_helikon_core::agent"` today, and this ticket silently changes it to `"paigasus::core::agent"`. §7.4 declares this "unaffected by this ticket". | Why it matters: D4's stated premise is not breaking the operator quietly, and this is precisely a quiet break — any saved search, sampling rule, or dashboard filter keyed on the OTel `target` **attribute** (not the span name) goes silent, and the migration section as specified says nothing about it. | Suggested fix: correct §7.4 to say span *names* are unaffected but the exported `target` **attribute** changes on every span and event (default-on), and add a row to §5.4's migration table covering OTel-attribute filters, not just `RUST_LOG`.

- **§7.4's spot check is not runnable as written** — `crates/paigasus-helikon/examples/langfuse_tracing.rs` installs `tracing_subscriber::registry().with(tracing_opentelemetry::layer()...)` (`:150-152`) with **no `EnvFilter` and no `RUST_LOG` handling at all**, and `main` hard-`?`s on `LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY` (`:133-134`), so it exits before emitting anything without live Langfuse credentials. | Why it matters: the one manual verification step for the highest-value change in the ticket cannot be performed as described; whoever implements it will improvise or skip it. | Suggested fix: rewrite §7.4 to name a concrete, runnable procedure — e.g. `crates/paigasus-helikon-runtime-agentcore/examples/echo_http.rs`, which already wires `EnvFilter::try_from_default_env()` (`:80-83`) — or state explicitly that the check requires temporarily adding an `EnvFilter` layer to the langfuse example.

- **D3's group selector is protected against under-matching but not over-matching, contradicting "this costs nothing to protect"** — the guard at `tests/workspace-lints/tests/tracing_target_docs.rs:192-206` rejects a component that is a prefix of another. That does stop a component named exactly `runtime`. It does **not** stop a future non-runtime component named `runtimeconfig`, `runtimes`, or `runtime2` — none of those is a prefix of, or prefixed by, any `runtime_*` name, so CI stays green while `paigasus::runtime` silently widens. | Why it matters: §5.2 publishes `paigasus::runtime` as a promise ("Every runtime adapter"), and the spec asserts the promise is mechanically protected when only half of it is. | Suggested fix: either state in D3 that the guarantee is "includes every runtime adapter", not "exactly", or extend the guard with a rule that any component starting with `runtime` must start with `runtime_` **and** correspond to a `paigasus-helikon-runtime-*` crate.

- **Nothing asserts that a component matches the crate it is emitted from — and there is already a counterexample in source** — `crates/paigasus-helikon-providers-litellm/src/translate/request.rs` emits `target: "paigasus::openai::translate"` from the *litellm* crate. Under the proposed shape guard and the existing docs guard, both pass. So after this ticket a file in `runtime-axum` could emit `paigasus::core::agent` (or vice versa) with a fully green build. | Why it matters: the entire operator value of D2 and D3 is "component ⇒ crate". A drifted site makes `paigasus::runtime_axum` miss events and `paigasus::runtime` miss a whole adapter, silently. §5.3 also keeps a book table whose "Crate" column is already inaccurate for that litellm site. | Suggested fix: add a fourth assertion — for each file under `crates/&lt;crate&gt;/src`, every target's component must be the component registered for `&lt;crate&gt;`, with an explicit, commented allowlist entry for the litellm→`openai` site — or, if that is out of scope, say so and record the exposure.

- **The `#[tracing::instrument]` blind spot makes §5.1's book claim untrue** — §5.1 tells the book to say "the coverage guard is what keeps that true". `try_scan`/the proposed `scan_untargeted` key on `ident !` followed by a delimiter (`tests/workspace-lints/src/lib.rs:129-158`); an attribute has no `!`, so `#[tracing::instrument]` is invisible to the guard. `crates/paigasus-helikon-macros/src/signature.rs:210` shows the `#[tool]` macro already forwards `#[tracing::instrument]` to the generated helper. §8 makes adding one a non-goal but never says the guard cannot see it. | Why it matters: publishing "complete by construction" in the book while the guard has a known bypass is exactly the blanket-claim-with-a-hidden-exception defect SMA-557 spent a review wave removing. | Suggested fix: extend the guard to reject any `#[tracing::instrument]` / `#[instrument]` attribute under `crates/*/src` that lacks `target = "paigasus::…"` (or reject the attribute outright, matching §8), and only then let the book say "by construction".

- **§7.1.1's rule 1 makes the EnvFilter test a second, invisible source of truth for the docs guard** — the analysis is correct as far as it goes (I traced both directions through `mask_trivia`/`scan_targets`/`component_of`; the fixture-as-literal claim in rule 2 holds, and `paigasus_helikon_core::session` correctly yields `None` from `component_of` at `tests/workspace-lints/src/lib.rs:238`). - **§4.3's escape hatch covers coverage but not shape, though both have identical exposure** — the marker suppresses `scan_untargeted`. §4.4 runs the shape loop over `scan_target_literals` unconditionally. ## Findings

### Minor 1 — D7's `#[tracing::instrument]` ban has two real bypasses
`tests/workspace-lints/src/lib.rs:637-668` (`instrument_attribute_lines`)

The backward walk strips **one** optional `::&lt;ident&gt;` qualifier and then requires `#[` immediately before. Empirically confirmed missed (guard ran **green**):
- `#[::tracing::instrument]` — a valid, idiomatic Rust attribute path (leading `::` to avoid shadowing). After stripping `tracing::` the walk sees `::`, not `#[`.
- `#[cfg_attr(test, tracing::instrument)]` — preceded by `, `, not `#[`.

Failure scenario: a contributor writes either form, CI stays green, and the span silently lands on its module path — the exact hole D7 exists to close. This *upgrades* deferred minor #1 from "hypothetical, no such form exists" to "two real forms, one of them a common idiom". Still Minor: nothing in the workspace uses either, adding `#[tracing::instrument]` at all is already a stated non-goal (spec §8), and the blast radius is degraded observability, not incorrectness. Fix is small — loop the qualifier strip instead of doing it once, and accept an attribute-interior context.

### Minor 2 — the book's reserved-component count is wrong, and `facade` contradicts its own derivation rule
`docs/book/src/concepts/observability-evaluation.md` ("Components reserved but not yet emitting")

The page says *"**Seven** crates have a name under this rule with no call site emitting on it yet"* and lists `mcp, tools, evals, cli, sessions_sqlite, sessions_postgres, sessions_redis`. `CRATE_COMPONENTS` (`tests/workspace-lints/tests/tracing_target_coverage.rs:50-72`) registers **ten** reserved names — additionally `facade`, `macros`, `sessions_testkit`. I confirmed eight crate directories contain no `tracing::` reference at all, including `paigasus-helikon-sessions-testkit`, so the count is wrong on its own terms.

Worse, the same paragraph states the derivation rule ("strip `paigasus-helikon-`, then a leading `providers-`, then `-`→`_`"), which for `paigasus-helikon` yields `paigasus_helikon`, **not** `facade`. A contributor who adds a log line to the facade and follows the documented rule gets a guard failure naming a component the book never mentions. (Loud, not silent — hence Minor.) The spec inherits the same "seven" error at §D6.

### Minor 4 — the escape-hatch suppression path is unreachable and untested
`tests/workspace-lints/tests/tracing_target_coverage.rs:271-284`

`assert!(allow_lines.is_empty(), …)` at `:273` fires before the per-invocation `suppressed` check at `:279-284`, so that branch can never execute. ### Minor 5 — a test name over-claims relative to what it probes
`tests/workspace-lints/tests/envfilter_semantics.rs:76` — `runtime_group_selector_reaches_every_adapter` asserts on `runtime_axum` and `runtime_tokio` only.

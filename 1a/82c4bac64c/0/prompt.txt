## 3. Usability &amp; API shape of the user-facing SDK

The old `temporal-sdk` prototype (`WfContext`/`ActContext`, "not for production") is **gone** — replaced by a redesigned macro-based SDK in `crates/sdk`. Current shape (verified from `crates/sdk/README.md`, `lib.rs`, and the hello-world example):

- **Activities**: `#[activities]` on an `impl` block, `#[activity]` per method: `async fn greet(_ctx: ActivityContext, name: String) -&gt; Result&lt;String, ActivityError&gt;`; shared state via `self: Arc&lt;Self&gt;`.
- **Workflows**: `#[workflow]` on a state struct + `#[workflow_methods]` impl with `#[init]` (constructor from `&amp;WorkflowContextView`), `#[run]` (async, `ctx: &amp;mut WorkflowContext&lt;Self&gt;` → `WorkflowResult&lt;T&gt;`), `#[signal]`, `#[query]`, `#[update]`. State access via `ctx.state(...)`/`state_mut(...)`. Activities invoked type-safely: `ctx.start_activity(MyActivities::greet, name, ActivityOptions::start_to_close_timeout(...))?.await?`.
- **Worker**: `CoreRuntime::new_assume_tokio(RuntimeOptions)` → `Connection::connect` → `Client::new` → `WorkerOptions::new("task-queue").register_workflow::&lt;W&gt;()?.register_activities(A).build()` → `Worker::new(&amp;runtime, client, opts)?.run().await`. Config via env vars / `temporal.toml` (`envconfig` feature).
- Coverage is broad: 15+ shipped examples (child workflows, continue-as-new, local activities, saga, schedules, cancellation, search attributes, message passing, heartbeating, interceptors, polling, updatable timers) plus experimental **WASM workflows** (`wasm-workflows` feature, wasmtime 44). `#![warn(missing_docs)]`; docs.rs builds cleanly: https://docs.rs/temporalio-sdk
- Supported and documented (docs.temporal.io section + Public Preview support status), but explicitly API-unstable pre-1.0.

## 5. Testing story

- **Local dev server**: yes — `temporal server start-dev` works as with every SDK. Better: `temporalio-sdk-core`'s **`ephemeral-server` feature** provides programmatic `TemporalDevServerConfig::start_server()` which can auto-download and cache the `temporal` CLI binary, and **`TestServerConfig`** which downloads/runs **`temporal-test-server` — the time-skipping test server** (verified in `crates/sdk-core/src/ephemeral_server/mod.rs`, incl. the `get_or_download("temporal-test-server", ...)` call).
- **Replay**: core-level `replay` module exists and is public in `temporalio-sdk-core` (doc: "used by Lang SDKs to provide replay capabilities to users during testing"; `HistoryInfo` public; canned histories behind the not-public-API `test-utilities` feature). **The high-level `temporalio-sdk` does not yet expose a polished replayer or time-skipping test harness** (no testing module in `crates/sdk/src`; the official Rust docs section has no Testing page). Equivalent of Python's `WorkflowEnvironment.start_time_skipping()` at SDK level: not yet — you'd wire core's `ephemeral_server` + `replay` directly.
- Practical today: dev-server/ephemeral-server integration tests (env-gate them, same pattern as Helikon's `sessions-it`/`forkd_live`). Replay tests: possible via core, rougher edges.

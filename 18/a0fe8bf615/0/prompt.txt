### Issues

#### Minor — `utoipa` workspace pin includes `"macros"` beyond spec

**Location:** `Cargo.toml:294`

```toml
utoipa = { version = "5.5.0", default-features = false, features = ["macros", "axum_extras"] }
```

**What's wrong:** The spec prescribes `features = ["axum_extras"]` only. The implementer added `"macros"`.

**Why it matters:** The workspace pin is shared — any future crate that does `utoipa = { workspace = true, optional = true }` silently gets `macros` pulled in too, even if that crate would prefer to opt in explicitly. The `macros` feature enables proc-macro derive impls (`ToSchema`, etc.) and is broadly additive and safe, but it's a deviation from the spec's stated pin.

**Fix:** Leave as-is — the addition is justified (utoipa 5.5.0 requires it for `PartialSchema` resolution), documented, and harmless. However, the deviation from the spec's pin should be noted in the commit message or a follow-up comment so future maintainers understand why `macros` appears in the workspace pin.

#### Minor — `reqwest` dev-dep carries no TLS features

**Location:** `crates/paigasus-helikon-runtime-axum/Cargo.toml:32`

```toml
reqwest = { workspace = true }
```

**What's wrong:** The workspace pin is `{ version = "0.13", default-features = false }` with no TLS. The other consuming crates (anthropic, tools, gemini) each add `features = ["...", "rustls"]` per-crate so they have a TLS backend. The runtime-axum dev-dep does not.

**Why it matters:** Running `cargo test -p paigasus-helikon-runtime-axum` in isolation means reqwest has no TLS backend; any test making HTTPS requests will fail at runtime. This task has no tests yet, so there is no immediate breakage. The workspace `--all-features` run sees other crates' `rustls` feature unified in, so TLS works there. No ring is introduced, so the CryptoProvider panic constraint is satisfied. This is a minor technical debt for future test authors.

**Fix:** When the first test using reqwest for HTTPS is written, add `features = ["json", "rustls"]` to this dev-dep entry. Not a blocker for this task.

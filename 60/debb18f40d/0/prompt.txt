### Named risks — all verified sound
1. **Cancel-on-disconnect:** One-shot binds the guard to a *named* `_disconnect` (runs.rs:355), so it lives to function-scope end across `collect().await` — not the `let _ =` footgun that would drop immediately. SSE threads the `DropGuard` through the unfold state `(events, disconnect)` and re-emits it each iteration (runs.rs:335-344), so it survives for the body's lifetime; client disconnect drops the body → state → guard → cancel. Async attaches none (runs.rs:228-229). Correct in all three.
2. **Lock lifetime/deadlock:** `OwnedMutexGuard&lt;()&gt;` is `Send`, moved into the writer, dropped exactly once at completion (runs.rs:309) and via unwind on panic. No std `Mutex` (`SessionLocks.map`) is ever held across an await — `lock_for` locks and releases synchronously before `.lock_owned().await`. Different sessions use different `Arc&lt;Mutex&gt;`, so no cross-session stall. No AB-BA cycle (registry `note_terminal` releases `terminal_at` before taking the write lock; registry/event-log/session locks never nest into a cycle).
3. **No-hang:** Both match arms call `mark_terminal()` before the writer can exit (runs.rs:296,305); the one-shot `subscribe(0).collect()` always observes terminal and returns. The only non-terminating case is an agent stream that never ends — an agent property, not a handler path, and the writer still cannot *exit* without a terminal.
4. **Prune race:** `map.retain(strong_count &gt; 1)` runs under the same `map` guard as the subsequent `entry().or_insert` (atomic). The arc returned by `lock_for` keeps count ≥ 2 until `.lock_owned()` consumes it (no gap in the method chain), and an in-flight writer's guard keeps count ≥ 2, so a concurrent same-session caller always converges on the pointer-equal `Mutex`. Recreating a fresh lock only happens when count == 1 (no live holder ⇒ no concurrent run ⇒ safe).
5. **start_error→500:** Checked after drain, returns `ServerError::RunStart` → 500 before building a 200 envelope (runs.rs:360-367; mapping at error.rs:86). The happens-before chain (writer writes `start_error`, then `mark_terminal` releases the EventLog mutex; reader observes terminal via that mutex, then reads `start_error`) guarantees the reader sees the value — no stale read.
6. **AC2 fidelity:** `to_sse_event` serializes the *full* `AgentEvent` as the `data:` payload (runs.rs:377-386); `parse_sse` reconstructs it; compact JSON means one event per `data:` line. Faithful event-for-event.
